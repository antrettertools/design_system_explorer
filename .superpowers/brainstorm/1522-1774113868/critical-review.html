Critical — Broken / Missing Core Functionality
Critical
No color editing in detail mode — entire Colors tab is read-only
The detail mode Colors tab shows beautiful shade scales but nothing is editable. Clicking a swatch only copies the hex to clipboard. There is no color picker, no hex input, no way to change any of the up-to-8 palette colors. overrideHex() exists in the store but is never called from any UI. This is the most fundamental gap — the whole point of detail mode is to refine.
// store/color.ts has overrideHex() — but no UI calls it // ShadeScaleSection.tsx: onClick → clipboard copy only // Missing: <input type="color"> or hex input per slot
Critical
Effects tab — 100% read-only despite store having full edit support
The store has overrideShadow(), resetShadow() fully implemented — but ShadowSection has no inputs to call them. FocusRingSection shows width/color/offset as display text only — no way to change them. MotionSection shows durations and easings as read-only labels. Users cannot modify a single effect token.
// ShadowSection.tsx: toggles colored/neutral but no per-step editing // FocusRingSection.tsx: displays focusRing.color/width/offset — display only // MotionSection.tsx: all values are read-only labels
Critical
Showcase templates only use the brand color — secondary/accent colors never appear
All 4 templates (Landing, Dashboard, Blog, System) use exclusively --color-interactive (brand). Secondary, Accent A, Accent B are computed and injected into :root but never referenced in any template CSS. State colors (error/warning/success/info) also never appear in templates. A 6-color palette looks identical to a 1-color palette in the showcase — completely defeating the multi-color system.
Critical
Dark/light mode: missing three-way background control + incomplete token coverage
Two problems: (1) The theme toggle is binary light/dark — but the user wants white / light-bg / dark-bg as three distinct options. (2) The dark token map only gets the outputs of deriveDarkModeRoles() — neutral and brand interactive roles. Many light-only tokens (state/mood colors, data viz, spacing, effects) have no dark counterpart, so hardcoded fallback colors bleed through in dark mode.
// store/derived.ts dark map only gets deriveDarkModeRoles() output // State/mood colors (--color-error, --color-success) have no dark version // AppTheme type = 'light' | 'dark' — needs third 'white' option
Critical
Type scale ratio is display-only — cannot be changed
ScaleEditor shows the scale ratio (e.g. 1.250) as a read-only label. The store has setScaleRatio() but it's never surfaced. Users can change the heading/body font via FontBrowser, but cannot change the modular scale ratio, font weights, line heights, or individual step sizes — all of which are the primary controls a designer would reach for in a typography detail mode.
Feature Gaps — Partially Implemented or Missing Sections
Gap
Colors tab: missing Greyscale section
The Colors tab has ShadeScales, SemanticRoles, DataViz, ContrastGrid. But there is no greyscale palette section. Greyscale is the invisible backbone of every UI — neutral surfaces, dividers, text hierarchy. The neutral roles exist in the token map (--color-background, --color-surface, etc.) but they're buried in SemanticRoles. There should be a dedicated visual greyscale strip from white to black.
Gap
Colors tab: missing Font Colors / Text Hierarchy section
Typical font colors (primary text, secondary text, disabled text, link color, placeholder) are semantic tokens already in the system (--color-on-surface, --color-on-surface-subtle, etc.) but completely invisible to users. There's no section showing what text colors will look like on the current backgrounds, no ability to override them, no visual hierarchy preview.
Gap
Components tab: only Button has a preview — 6 others are blind
Token overrides for input, card, badge, tag, tooltip, and alert can be typed into text inputs — but there's no visual preview to see the effect. The Button accordion shows a "Preview: [Button] [Hover]" section. Every other component is text-in, void-out. Users are flying blind. Minimum: a rendered specimen for each component using its own --component-* vars.
Gap
Icon libraries: placeholder SVGs only — no real icons
IconLibrarySection shows a grid of 24 generic placeholder SVG circles with stroke hints — but clicking Lucide, Heroicons, Phosphor, Tabler, or Radix shows the same squares. No actual icon packages are installed. Switching library changes store state but the visual output is identical for all 5. Phase 4 was meant to install lucide-react etc. — this is still outstanding.
Gap
ShowcaseTab has no useful controls — "Data Viz Colors" is static text
The Showcase tab currently offers: template picker (4 options), theme toggle, fullscreen button, and share link. The "Data Viz Colors" section is a single line of read-only text: "5-color categorical palette — adjust in Colors tab". No swatch preview, no inline control — just a breadcrumb to somewhere else. This entire section should be removed or replaced with a real mini-preview or an inline count stepper.
Gap
Spacing tab: radius and misc sections have no visual editing
SpacingScaleSection has proper number inputs with live bar visualization. But RadiusSection and MiscSection likely follow the same text-only or read-only pattern. Border radius especially benefits from a visual preview of rounded corners at each step — showing a box with the applied radius — rather than just a number.
UI/UX Problems — Readability, Affordance, Hierarchy
UX
Text sizes too small throughout the app — accessibility failure
Multiple places use 10–12px text in critical UI chrome — not just the live preview template. Examples: ScaleEditor ratio row has inline fontSize: 10. ShowcaseTab has fontSize: 11. SpacingScaleSection "base unit" hint: fontSize: 10. The engineering guide says body = 16px, label = smallest usable. Minimum readable size for UI chrome is 12px; for labels indicating state, 13px. The app itself should model good type scale practice.
// ScaleEditor.tsx:29 — fontSize: 10 inline // ShowcaseTab.tsx:95 — fontSize: 11 inline // SpacingScaleSection.tsx:37 — fontSize: 10 inline // Multiple CSS modules use 10–11px sectionTitle labels
UX
Color swatches have no edit affordance — zero discoverability
In generator mode, hovering a ColorSlotCard does nothing to suggest it's editable. There's no edit icon, no cursor change, no "click to change" tooltip. Users who want to pick a specific color have no discoverable path to do so. At minimum, an edit icon (✎) or color-picker swatch overlay should appear on hover to signal editability.
UX
Theme toggle uses cryptic symbols — ◐ and ○ are not universally understood
The AppHeader theme toggle uses ◐ for light mode and ○ for dark mode. These are not standard icons — a half-circle and empty circle have no universal meaning for theme switching. Standard practice is a sun (☀) / moon (🌙) or a filled/outlined variant. The ShowcaseTab also toggles theme with "◐ Switch to dark mode" — same confusing symbol. With the planned three-option background system, this needs a redesign anyway.
UX
AppHeader is too minimal — no visual hierarchy or context
The header has: wordmark "palette." + a clock SVG icon (sessions) + a cryptic symbol (theme) + "Export ↓" button. The sessions icon (clock SVG) gives no indication it opens a sessions drawer. There's no current mode indicator, no undo/redo controls, no hint at keyboard shortcuts. The header should communicate state: what mode you're in, what harmony model is active, whether you're looking at a saved session.
UX
DetailMode top bar: tab navigation is too compressed at small widths
The detail mode nav shows: ← Generator | Colors | Typography | Spacing | Effects | Components | Showcase | Export — all in one line. With 7 tabs plus a back button, this is extremely tight on any non-wide viewport. There's no overflow handling, no active tab highlighting that draws the eye, no keyboard shortcut to jump between tabs. Tab labels are the only navigation — no icons.
UX
Contrast grid is isolated — no inline WCAG pass/fail explanation
The ContrastGrid presumably shows contrast ratios between color combinations. But there's no legend explaining what the numbers mean, no color-coding to indicate AA (4.5:1) vs AAA (7:1) pass/fail, no context about which text sizes these ratios apply to. A contrast grid without WCAG context is just numbers.
UX
Generator panel: undo/redo (Cmd+Z) is invisible — no UI hint
The app supports full undo/redo via Zustand temporal middleware (up to 50 states), but this is completely undiscoverable — there are no undo/redo buttons, no history indicator, no mention in the UI. Only keyboard shortcuts (Cmd+Z / Cmd+Shift+Z) work, and only users who read the code would know. This is a major feature that should be surfaced.
Architecture Violations
Arch
ComponentsTab.tsx uses inline styles — violates CSS Modules rule
The engineering guide is explicit: "CSS Modules only. No inline styles." ComponentsTab.tsx wraps its content in a <div> with style={{ display: 'flex', flexDirection: 'column', gap: 'var(--spacing-xl)', ... }}. This is a direct violation. The wrapper styles should be in ComponentsTab.module.css.
// ComponentsTab.tsx:6-13 — inline style block // Should be: <div className={styles.tab}> // With .tab { display: flex; flex-direction: column; ... } in .module.css
Arch
Multiple components import from core/ directly — bypassing the store contract
Rule: "Components and features import only from store/. Never from core/ directly." Violations found: ShadeScaleSection.tsx imports makeShadeScale from @/core/color/scales. SemanticRolesSection.tsx imports from @/core/color/semantic and @/core/color/darkMode. SystemTemplate.tsx imports from 4 core modules directly. This creates hidden dependencies that bypass the store as the single source of truth.
// ShadeScaleSection.tsx:3 — import makeShadeScale from '@/core/color/scales' // SemanticRolesSection.tsx:2–4 — 3 core imports // SystemTemplate.tsx:1–5 — 4 core imports // These should derive from store-computed token map instead
Recommended sequencing: Fix the critical issues first (color editing, effects editing, showcase colors, dark mode coverage). Then address feature gaps (greyscale, font colors, component previews). UX and arch improvements can be batched. The two arch violations should be fixed opportunistically during any file touch.
