# Spec 04 — Live Showcase Redesign

**Spec date:** 2026-04-12  
**Phase:** 1 (browser chrome frame, template picker, PREVIEW chip, removals) and 2 (interactivity, scroll signposting, template thumbnails in ShowcaseTab)  
**Status:** Specced — not yet implemented

---

## What This Covers

The redesign of `LivePreview.tsx` and the four template components. The showcase is the product's most persuasive surface. The redesign makes it interactive, framed, and explorable — elevating it from "pretty preview" to "undeniable proof of concept."

---

## Current State (verified against codebase)

`LivePreview.tsx` renders:
- A `styles.panel` div (scrollable, ref'd for scroll-to-top)
- A `styles.backBtn` (mobile only — "← Back to generator")
- The active template via `renderTemplate()` switch

Template selection logic:
```tsx
// Generator mode always shows landing; detail mode uses showcaseTemplate store value
```

Template switching currently lives **only** in `ShowcaseTab.tsx` inside Detail Mode.

Templates (verified file paths):

## Browser Chrome Frame (Phase 1)

A lightweight browser-chrome frame added at the top of `LivePreview`, above the template content. It does three jobs: signals "this is a preview," makes the showcase feel like a real product, and creates a natural container.

### Spec

| Property | Value |
|---|---|
| Frame height | 36px |
| Three dots | 12px circles: `#FF5F57`, `#FEBC2E`, `#28C840` — standard browser signifier |
| URL bar content | Active system name from store, or `yourproject.dsygn.cloud` as fallback |
| URL bar style | Rounded rect, `background: var(--color-surface-raised)`, `color: var(--color-on-surface-subtle)` |
| Frame background | `var(--color-surface)` — blends with system tokens |
| Refresh icon | Present (`<RotateCw size={12} />` from Lucide), non-functional, `title="Hit SPACE to regenerate"` |
| Frame border-bottom | `1px solid var(--color-border)` |
| Three-dot colors | Hardcoded hex — these are a universal browser signifier, not themed |

### Persistent Template Picker (Phase 1)

The template picker moves from `ShowcaseTab` (Detail Mode only) to the browser chrome frame — making it accessible from **both Generator and Detail Mode**.

**Current behaviour (verified):** In generator mode, `LivePreview` hardcodes `const template = mode === 'detail' ? showcaseTemplate : 'landing'`. This must change.

**New behaviour:**
- Four template pills rendered in the browser chrome bar: `Landing` · `Dashboard` · `Blog` · `System`
- Clicking any pill calls `setShowcaseTemplate(id)` — same store action, same `showcaseTemplate` state
- Remove the hardcoded `'landing'` override for generator mode: always use `showcaseTemplate`
- `showcaseTemplate` defaults to `'landing'` in the store (verify this default is set) — so first load is unchanged
- The template selector in `ShowcaseTab.tsx` remains as-is (it will be replaced by thumbnails in Phase 2, per spec 03) — both selectors set the same store value, no conflict

**Template pill style:**
- Active: `background: var(--color-interactive)`, `color: var(--color-on-interactive)`, `border-radius: var(--radius-full)`
- Inactive: `background: transparent`, `border: 1px solid var(--color-border-strong)`, `color: var(--color-on-surface-subtle)`, `border-radius: var(--radius-full)`
- Hover inactive: border → `var(--color-interactive)`
- Pill height: 20px, padding: `2px 10px`, `font-size: var(--ui-text-sm)`
- Pills sit to the right of the URL bar in the chrome frame

**File changes:**
| File | Change |
|---|---|
| `LivePreview.tsx` | Add chrome frame `<div>` above template content. Import `useUIActions`, `useUI`. Add template pills. Remove `mode === 'detail' ? showcaseTemplate : 'landing'` hardcoding — always use `showcaseTemplate`. Keep all existing template switch logic and `panelRoute` sub-routing. |
| `LivePreview.module.css` | `.chromeFrame`: 36px height, flex row, border-bottom, `background: var(--color-surface)`. `.dots`: flex, gap. `.dot`: 12px circle. `.urlBar`: rounded rect, `var(--color-surface-raised)`. `.templatePills`: pill row styles. `.pill` + `.pillActive`. |

## Showcase Interactivity (Phase 2)

The showcase becomes lightly interactive — enough to prove the design system's interaction states are real. Not a functional app.

**Implementation approach:** Add CSS interaction states to the template components via their existing CSS modules. No new store state. No JS event handlers beyond `preventDefault` on navigation links.

### Interaction specs by element type

| Element | Interaction | Implementation |
|---|---|---|
| Primary buttons | Hover: `background: var(--color-interactive-hover)`, `transform: scale(0.98)`. Active: `scale(0.96)` | CSS `:hover` + `:active` in template CSS modules |
| Destructive buttons | Hover: `background: var(--color-error-container)` | CSS `:hover` |
| Input fields | Click → focus ring: `outline: var(--focus-ring-width) solid var(--focus-ring-color)`, `outline-offset: var(--focus-ring-offset)` | CSS `:focus` — inputs already focus natively |
| Cards | Hover: increase shadow level (e.g., `--shadow-md` → `--shadow-lg`) | CSS `:hover` on card containers |
| Badges | Not interactive (informational only) | No change |
| Navigation links | `onClick: e => e.preventDefault()` + tooltip on click: `"Preview mode"` | Add `onClick` handlers in `DsygnLanding.tsx` |
| Dark mode transition | 300ms cross-fade using CSS transitions on CSS variables (already mostly in place via meta-theming) | Verify `transition` on color properties in templates |

**File changes:**
| File | Change |
|---|---|
| `LandingTemplate/DsygnLanding.tsx` | Add `onClick={e => e.preventDefault()}` to navigation links. |
| Template CSS modules | Add `:hover` states on buttons, cards. Add `:active` scale transforms on buttons. Add `:focus` ring styles on inputs. |

## Scroll Signposting (Phase 2)

Users currently miss content below the hero section of the showcase. Three additions:

### 1 — Scroll Progress Indicator
- Thin 2px vertical line on the right edge of the showcase `styles.panel`
- A small dot shows current scroll position (ratio of `scrollTop / scrollHeight`)
- Line and dot tinted in `var(--color-interactive)`
- **Invisible until the user first scrolls** (`opacity: 0` → `opacity: 1` on first scroll event, `transition: opacity 200ms`)
- Implementation: track `scrollTop` on the `panelRef` scroll event in `LivePreview.tsx`. Compute dot position as `(scrollTop / (scrollHeight - clientHeight)) * 100%`. Update a CSS custom property `--scroll-progress` on the panel.

### 2 — Section Anchors (floating pill)
- Floating pill visible only on hover of the right edge of the showcase panel
- Shows: `Hero · Colors · Type · Components · Spacing · Pricing`
- Clicking any anchor smooth-scrolls to that section within `panelRef`
- Each template must have its sections marked with `id` attributes for scroll targeting
- Implementation: absolutely positioned pill, `opacity: 0` by default, `opacity: 1` on panel hover. Anchor IDs added to relevant template sections.

### 3 — "Scroll to Explore" Hint
- On first load: a small downward chevron (`<ChevronDown />`) at the bottom of the visible viewport, pulses twice (CSS animation), then disappears
- **Never appears again after the first scroll** — use `sessionStorage` flag
- Implementation: local state in `LivePreviewContent`. On first scroll event: hide the hint and set `sessionStorage.setItem('scrollHintSeen', '1')`. On mount: check `sessionStorage` and skip if already seen.

**File changes:**
| File | Change |
|---|---|
| `LivePreview.tsx` | Add scroll event listener on `panelRef`. Track scroll progress. Add scroll progress indicator element. Add section anchor pill. Add scroll hint chevron with sessionStorage logic. |
| `LivePreview.module.css` | `.progressLine`, `.progressDot`, `.anchorPill`, `.scrollHint` styles. |
| Template TSX files | Add `id` attributes to major sections for anchor targeting. |
