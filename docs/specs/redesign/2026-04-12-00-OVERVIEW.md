# dsygn.cloud — Design Redesign: Master Overview

**Spec date:** 2026-04-12  
**Scope:** Generator · Detail Mode · Showcase · Mobile  
**Status:** Specced — not yet implemented

---

## The One Idea

> **The tool wears its own output.**

Every chip, button, card, shadow, and typographic element in the dsygn.cloud UI is styled by the CSS tokens from the currently active design system. When the user hits SPACE and the palette shifts from teal to violet, the generator panel itself shifts with it. This is the most powerful demonstration the product can make — the generator *is* the first showcase.

Everything in this redesign serves that premise. Visual hierarchy changes, de-cluttering, mobile strategy — all of it is in service of making that one idea as clear and undeniable as possible.

---

## Design Principles

### 1 · Surface the Signal, Bury the Noise
Foreground one thing at a time. The brand color, the font pair, the live showcase — these are the signal. Hex values, OKLCH coordinates, token names, configuration knobs — these are the noise. Noise is available but never competes with signal for visual attention. The default state of every panel should be beautiful. The technical layer lives one interaction deeper.

**In practice:** Hex values appear on hover only. OKLCH coordinates live behind a toggle. Token names are secondary text. The dominant visual in every section is the color or font itself — not its metadata.

### 2 · Emphasize Through Contrast, Not Decoration
Nothing is made important by adding more to it. A brand color swatch is made important by giving it more space, more silence around it, and removing everything that competes. No gradients, illustrations, or ornamental detail. Emphasis through scale, whitespace, and restraint.

### 3 · Progressive Disclosure — The Iceberg Model
Generator Mode is the surface. Detail Mode is the depth. The Generator shows exactly what is needed to generate a good system, and nothing more. Detail Mode reveals everything for users who want full control. Nothing that belongs in Detail Mode leaks into the Generator, and vice versa.

### 4 · Mobile is a First-Class Context, Not a Scaled-Down Desktop
The split-panel layout is a desktop pattern. On mobile, the showcase is the primary experience and the generator is a contextual bottom-sheet panel. Mobile is designed separately from first principles, sharing only the token system and component library.

## What Does NOT Change

These features and patterns are correct as-is and must be preserved completely:

| Area | What stays |
|---|---|
| Core architecture | 50/50 split panel. `GeneratorPanel` / `DetailMode` switching. `LivePreview` always on the right. |
| SPACE mechanic | Keyboard shortcut as primary regeneration mechanic. |
| Detail Mode tab order | Colors → Typography → Spacing → Effects → Components → Showcase → Export |
| APCA scoring | The 102 Lc "Excellent" badge in Typography. Keep score, label, and position. |
| Four showcase templates | Landing, Dashboard, Blog, System — correct scope, do not change. |
| Three-state focus ring preview | Unfocused → Hover → Focused demo in Effects tab — keep exactly as-is. |
| 5 icon library options | Lucide, Heroicons, Phosphor, Tabler, Radix Icons + icon token table. |
| Share link mechanic | `encodeShare` / `loadFromHash` — keep mechanic, elevate its placement. |
| Zustand store | All slices, selectors, temporal undo/redo — no changes to state shape. |
| CSS Modules + CSS vars | All styling via CSS Modules consuming `var(--token-name)`. No inline styles. No Tailwind. |
| TypeScript strict mode | Zero `any`, zero `@ts-ignore`, zero `as unknown as X`. |
| Layer rule | `core/ → store/ → components/ + features/`. No skipping layers. |

## Architecture Context

```
App.tsx
├── AppHeader
├── SplitPane
│   ├── LEFT: <GeneratorPanel /> OR <DetailMode />  (mode === 'generator' | 'detail')
│   └── RIGHT: <LivePreview />                       (always rendered, always token-live)
├── ExportPanel (overlay)
├── SessionsDrawer (overlay)
├── SignInPrompt / UpgradeModal / DonateModal (overlays)
└── OnboardingOverlay
```

**Template switching** currently lives only in `ShowcaseTab` inside Detail Mode, and `LivePreview` is hardcoded to `'landing'` in generator mode. The redesign adds a persistent template picker to the `LivePreview` panel itself (inside the new browser chrome strip — see spec `04-SHOWCASE`), so template selection is available in both Generator and Detail Mode without changing any store shape.
