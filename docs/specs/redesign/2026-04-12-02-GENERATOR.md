# Spec 02 — Generator Mode Redesign

**Spec date:** 2026-04-12  
**Phase:** 1 (Zones 1 + 2 + SPACE badge + Detail Mode entry) and 2 (Zone 3 System Snapshot)  
**Status:** Specced — not yet implemented

---

## What This Covers

The complete visual redesign of `GeneratorPanel` and all its child components. The panel is restructured into three distinct zones stacked vertically, filling the full panel height with no dead space. No features are removed — everything is reorganized for clarity and hierarchy.

---

## Current State (verified against codebase)

`GeneratorPanel.tsx` renders:
1. `<SpaceHintBar />` — a plain bar reading "Hit SPACE to regenerate"
2. A `Colors` section: `<RecipePillRow />` + `<ColorSwatches />`
3. A `Typography` section: `<TypographySpecimen />`
4. `<GeneratorFooter />` — a small row with a "Detail Mode →" button (plus mobile-only Preview/Generate buttons)

### Current problems
- `SpaceHintBar` is plain text in a bar — not a tactile SPACE badge, easy to miss
- `RecipePillRow` harmony chips are below the section title, not above the swatches where they belong
- All color swatches are the same size — no visual hierarchy between brand and accents
- `ShadeStrip` is coupled to the lock state (`{slot.locked && <ShadeStrip />}`) — lock and shade-picking are the same gesture, which is confusing
- Role labels (`POSITION_LABELS`) render as normal-case text — brief requires ALLCAPS display
- `TypographySpecimen` shows a compact scale table — does not foreground the font pair as a visual specimen
- "Detail Mode →" button is a small corner element — does not signal its importance
- `~40%` of the panel is dead space below the typography section

## SPACE Badge — `SpaceHintBar.tsx` (Phase 1)

### Current
Plain `<div>` with `<kbd>SPACE</kbd>` text — no animation, no visual weight.

### New behaviour
- Replace plain bar with a keyboard-key illustration: rounded rect, label "SPACE" in `--font-body` / `--ui-font-body`, `--radius-md`
- Centered above the brand swatch
- **First load only:** 3 slow CSS pulses (`box-shadow` glow using `--color-interactive`), then stops — never repeats
- On SPACE press: brand swatch scales to `0.98` then back with spring easing (`cubic-bezier(0.34,1.56,0.64,1)`, 120ms)
- **All-locked state:** badge appearance changes — muted color + tooltip "Unlock something to regenerate"
- `prefers-reduced-motion`: replace pulse and scale with instant state change, no animation

### File changes
| File | Change |
|---|---|

### 1c — Lock / Shade Picker Separation (`ColorSlotCard.tsx`, `ShadeStrip.tsx`) — MOST IMPORTANT INTERACTION CHANGE

**Current (verified):**
```tsx
// ColorSlotCard.tsx line 146
{slot.locked && <ShadeStrip hex={slot.hex} role={slot.role} />}
```
`ShadeStrip` appears only when the card is locked. Lock and shade-picking are the same gesture.

**New behaviour — two completely independent affordances:**

**Lock toggle:**
- Lock button remains in top-right corner of swatch — single click toggles `locked`
- Locked: filled `<Lock />` icon, colored `var(--color-interactive)`, **plus** a 2px border on the card in `var(--color-interactive)` as secondary confirmation
- Unlocked: outline `<LockOpen />` icon, colored `var(--color-on-surface-subtle)`
- Locked cards do NOT change on SPACE — this logic is already correct in the store

**Shade picker (independent of lock):**
- On desktop: hover the swatch card → `ShadeStrip` slides up from below the card with a CSS spring animation (translate Y from 100% to 0, 180ms)
- On mobile: long-press (400ms, already implemented in `ColorSwatches.tsx`) → `ShadeStrip` appears
- Clicking a step in `ShadeStrip` calls a new action `pinShade(slotId, step)` — pins that shade as the base for this role and closes the strip
- A dot indicator below the swatch shows which step is currently pinned (no dot = default/auto)
- `ShadeStrip` must accept an `onSelectStep` callback prop and a `selectedStep` prop

**Store requirement:** A `pinShade(slotId: string, step: ShadeStep)` action is needed on the color slice. This stores the pinned step per slot. On SPACE, if a slot has a pinned step, the generator uses that step as the base for that slot's new color. If no step is pinned (default), generation is unconstrained.  
> Check `store/color.ts` before implementing — it may already have this or a similar mechanism.

**File changes:**
| File | Change |
|---|---|
| `ColorSlotCard.tsx` | Remove `{slot.locked && <ShadeStrip />}`. Add `const [shadeOpen, setShadeOpen] = useState(false)`. Add `onMouseEnter={() => setShadeOpen(true)}` / `onMouseLeave={() => setShadeOpen(false)}` on the card. Render `{shadeOpen && <ShadeStrip ... />}`. Add `pinnedStep` prop from slot state. Lock icon color via CSS class, not inline style. Add locked-border CSS class. |
| `ShadeStrip.tsx` | Add `onSelectStep?: (step: number) => void` prop. Add `selectedStep?: number` prop. On cell click: call `onSelectStep(step)`. Show dot indicator on the cell matching `selectedStep`. Add slide-in CSS animation. Keep `getComputedStyle` approach for reading token hex values — it already works correctly. |
| `ColorSlotCard.module.css` | Add `.locked` modifier: `box-shadow: 0 0 0 2px var(--color-interactive)`. Lock icon colors via CSS data attributes or class modifiers. |
| `store/color.ts` | Verify whether `pinShade` exists. If not: add `pinnedStep?: ShadeStep` to `ColorSlot` type and a `pinShade(id, step)` action. |

## Zone 2 — Type Pair (Phase 1)

### Current (`TypographySpecimen.tsx` verified)
Shows: section title "Typography" + lock-all button, font pair name as small text, lock pills (Heading / Body / Scale), editable specimen inputs (one for heading, one for body), and a full type scale row list.

### New behaviour — visual specimen first

The typography section in the Generator is reduced to the single most important thing: the font pairing as a large visual specimen.

**What moves to Detail Mode:** Scale ratio selector, all scale rows (H1–XS), the `ScaleEditor`. These stay in `TypographyTab` where they belong. They do NOT currently appear in the Generator... wait — re-checking the `TypographySpecimen.tsx`: it does show scale rows. These scale rows should NOT appear in the Generator per the brief's iceberg model. They belong in Detail Mode only.

**New Generator typography section:**
```
┌─────────────────────────────────┐
│  Petrona                [🔒]    │  ← heading font name, rendered in Petrona ~28px bold
│  "The quick brown fox"          │  ← sample text in heading font, ~18px
│  ─────────────────────────────  │
│  Mulish                 [🔒]    │  ← body font name, rendered in Mulish ~18px regular
│  "One line of body copy."       │  ← sample text in body font
└─────────────────────────────────┘
```

- Heading font name: `font-family: var(--font-heading)`, ~28px, `font-weight: 700`
- Sample heading text: first 5 words of pangram, same font, ~18px
- Lock icon (heading): `<Lock />` / `<LockOpen />` in top-right — calls `toggleLock('heading')`
- Body font name: `font-family: var(--font-body)`, ~18px, `font-weight: 400`
- Sample body text: one short sentence, same font
- Lock icon (body): `<Lock />` / `<LockOpen />` — calls `toggleLock('body')`
- **Scale lock pill:** Keep the Scale lock toggle — render it as a small "Scale" chip below the body specimen (it locks the ratio, which is not visible but still useful)
- **Click font name** → opens `FontBrowser` as a slide-in panel from the right. `FontBrowser` already exists in `TypographyTab/FontBrowser.tsx`. It needs to be extractable to a shared location OR imported from `TypographyTab` — see note below.
- The editable specimen text inputs: keep them, but make them inline-editable by clicking the sample text directly (not separate input boxes). Use `contentEditable` or keep as hidden `<input>` triggered by clicking the specimen text.
- **Scale rows removed from Generator** — they live in Detail Mode only

**Font Browser access from Generator:**
`FontBrowser.tsx` currently lives in `TypographyTab/`. For Phase 1, the simplest approach: when the user clicks a font name in the Generator, set `mode` to `'detail'` and set `activeTab` to `'typography'`, which scrolls the user to Detail Mode Typography where the full Font Browser is accessible. A full slide-in panel version of FontBrowser accessible from Generator is a Phase 2 refinement (spec it in `03-DETAIL-MODE` as the `FontBrowser` extract task).

**What stays the same:** All `toggleLock`, `lockAllTypography`, `unlockAllTypography` store calls. `pairing` and `scale` from `useTypography()`. The heading/body text sample state.

**File changes:**
| File | Change |
|---|---|
| `TypographySpecimen.tsx` | Full visual redesign of the JSX. Remove scale rows rendering. Remove compact lock pills row. Add large font name `<span>` elements with inline `fontFamily`. Add individual lock icons per font. Add "click to enter Detail Mode typography" handler on font name. Keep `headingText` / `bodyText` state but make specimen text editable inline. Keep Scale lock chip. |
| `TypographySpecimen.module.css` | New styles: `.fontName` (large, bold, family var), `.sampleText` (medium, family var), `.lockIcon` (positioned top-right of each font block), `.scaleChip` (small lock pill for scale ratio). Remove old scale row styles. |

## Zone 3 — System Snapshot (Phase 2)

This is a new component, replacing the dead space below the typography section. It is **read-only** — no editing, only preview. Each element navigates to the relevant Detail Mode tab when clicked.

### New component: `SystemSnapshot.tsx`

**Location:** `src/features/generator/SystemSnapshot/SystemSnapshot.tsx`

**What it shows:**

| Element | Content | Click action |
|---|---|---|
| Token count badge | `"47 tokens · 9 type steps · 4pt grid"` — counts derived from store state | No action — informational |
| Radius preview | Three small squares showing `--radius-sm`, `--radius-md`, `--radius-full` | `setMode('detail')` + `setActiveTab('spacing')` |
| Shadow preview | Small card (60×36px) with `box-shadow: var(--shadow-md)` applied | `setMode('detail')` + `setActiveTab('effects')` |
| Semantic swatches | 4 dots: `var(--color-error)`, `var(--color-warning)`, `var(--color-success)`, `var(--color-info)` | `setMode('detail')` + `setActiveTab('colors')` |
| Data viz strip | Horizontal strip of `dataVizN` color cells (same as `ShowcaseTab`'s dataviz strip) using `var(--color-dataviz-N)` | `setMode('detail')` + `setActiveTab('colors')` |

**Token count calculation:**
```
tokenCount = all keys in buildTokenMap output for current state
typeSteps  = Object.keys(scale).length (from useTypography())
gridPt     = baseUnit (from useSpacing())
```
Read from store via `useTypography()`, `useSpacing()`, and a count of token keys (can be a derived value or computed inline).

**File changes:**
| File | Change |
|---|---|
| `src/features/generator/SystemSnapshot/SystemSnapshot.tsx` | New file. Import `useTypography`, `useSpacing`, `useEffects`, `useColor`, `useUIActions`. Render token count badge + radius squares + shadow card + semantic dots + dataviz strip. All clickable. |
| `src/features/generator/SystemSnapshot/SystemSnapshot.module.css` | New file. Layout styles. All colors via `var(--color-*)`. |
| `GeneratorPanel.tsx` | Import and render `<SystemSnapshot />` between Typography section and GeneratorFooter. |
