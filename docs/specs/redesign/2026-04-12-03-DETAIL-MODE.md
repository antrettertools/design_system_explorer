# Spec 03 — Detail Mode Redesign

**Spec date:** 2026-04-12  
**Phase:** 2 (all items unless noted)  
**Status:** Specced — not yet implemented

---

## What This Covers

The visual redesign of `DetailMode.tsx` and all its tab components. The goal is not to reduce depth — Detail Mode earns credibility with senior designers. The goal is to present existing depth with visual quality it deserves: each tab should feel like a page in a beautifully crafted design system documentation site.

No tab is removed. No feature is removed. Tab order is unchanged: Colors → Typography → Spacing → Effects → Components → Showcase → Export.

---

## Tab Bar Redesign — `DetailMode.tsx` (Phase 2)

### Current
Plain text tabs with an underline active indicator. No icons. Not sticky.

### New behaviour
- **Sticky** tab bar: `position: sticky; top: 0; z-index: var(--z-10)` — stays visible as content scrolls
- **Background:** `var(--color-surface)` (meta-themed)
- **Active tab indicator:** 3px bottom border in `var(--color-interactive)`
- **Active tab label:** `color: var(--color-interactive)`
- **Inactive tab label:** `color: var(--color-on-surface-subtle)`
- **Tab icons:** Lucide icons, one per tab:
  - Colors → `<Palette />`
  - Typography → `<Type />`
  - Spacing → `<Ruler />`
  - Effects → `<Sparkles />`
  - Components → `<Layers />`
  - Showcase → `<Eye />`
  - Export → `<Download />`
- Icon + label visible on desktop. Icon-only on mobile (tooltip on tap) — mobile spec in `06-MOBILE`.
- **"← Generator" ghost button** at the left of the tab bar — always reachable. Calls `setMode('generator')`. Ghost style: no background, `color: var(--color-on-surface-subtle)`, hover: `color: var(--color-interactive)`.
- 150ms transitions on tab indicator color and label color.

**File changes:**
| File | Change |
|---|---|
| `DetailMode.tsx` | Import Lucide icons. Add icon to each tab definition object. Render "← Generator" ghost button left of tabs. Keep all existing `setActiveTab` calls and `activeTab` state. |
| `DetailMode.module.css` | Tab bar: `position: sticky; top: 0`. Active indicator: `border-bottom: 3px solid var(--color-interactive)`. Active label: `color: var(--color-interactive)`. Inactive label: `color: var(--color-on-surface-subtle)`. Add transitions. Ghost button styles. Background: `var(--color-surface)`. |

## Colors Tab — `ColorsTab/` (Phase 2)

### Shade Scales — `ShadeScaleSection.tsx`

**Current:** Thin horizontal strip of shade cells with step numbers.

**New behaviour:**
- Each color role gets its own named **full-width gallery card**: `background: var(--color-surface-raised)`, `border-radius: var(--radius-md)`, `box-shadow: var(--shadow-sm)`
- Role name displayed in `--font-heading` at `--ui-text-sm` / 600 weight / uppercase at top of card
- The 11 tonal steps (50–950) display as a **single row of equal-width squares**, each `~40px tall`
- On hover/tap of a step cell: hex value replaces step number with a copy-to-clipboard animation (briefly shows "✓")
- Currently active "base" step: marked with a small circle dot indicator below its square
- OKLCH values: hidden by default. A `Technical details` toggle button at the right of the card title reveals them as a compact table inline — no page jump, no new modal

**File changes:**
| File | Change |
|---|---|
| `ShadeScaleSection.tsx` | Wrap each scale in a card div. Increase cell height to ~40px. Add hover handler to swap step number ↔ hex + clipboard copy. Add active-step dot indicator. Add `Technical details` toggle (local `useState`). |
| `ShadeScaleSection.module.css` | `.card`: full-width, surface-raised, radius-md, shadow-sm. `.cell`: `flex: 1; height: 40px`. `.cellLabel` hover state. `.oklchTable`: initially hidden, revealed on toggle. |

- On each surface rectangle, interactive and on-interactive tokens are shown as colored blocks overlaid on the surface
- This communicates the relationship between tokens spatially — "on this surface, this is what your interactive color looks like"
- Read-only — no editing

**File changes:**
| File | Change |
|---|---|

### WCAG Contrast Grid — `ContrastGrid.tsx`

**Current (verified):** Renders contrast ratio rows (e.g., "Accent A / Accent C: 3.0:1 AA") — a linear list.

**New behaviour — heatmap grid:**
- Each cell = a color pair shown as a mini preview (small colored rect on a background) + ratio badge + AA/AAA pass/fail
- Grid layout: rows = foreground colors, columns = background colors
- Failing pairs (below AA): cell background tinted with `--color-error-container`, small "✗" indicator
- Passing AAA pairs: cell background subtly tinted with `--color-success-container`, "AAA" badge
- Passing AA-only pairs: neutral cell, "AA" badge
- Grid is scannable at a glance — no need to read row by row

**File changes:**
| File | Change |
|---|---|
| `ContrastGrid.tsx` | Replace list rendering with a CSS grid. Each cell: mini swatch preview + ratio + pass/fail badge. Conditional background tinting based on pass level. |
| `ContrastGrid.module.css` | Grid layout. Cell styles. Pass/fail color classes. |

## Typography Tab — `TypographyTab/` (Phase 2)

### Font Pair Display — `FontPairCard.tsx`

**Current:** Assumed to show font names as form fields or compact display.

**New behaviour — editorial specimens:**
- **Heading font:** large specimen, 48px, in the heading font itself. Sample text: "The quick brown fox jumps over the lazy dog." Font name below in small-caps style + weight range + lock icon.
- **Body font:** paragraph of body copy (~16px) in the body font. Font name below + weight range + lock icon.
- Clicking either specimen → opens `FontBrowser` as a **slide-in panel from the right** (see Font Browser section below)
- Lock icons call `toggleLock('heading')` / `toggleLock('body')` — same store actions, new visual position

**File changes:**
| File | Change |
|---|---|
| `FontPairCard.tsx` | Redesign rendering: large `<p>` specimen for each font. Add click handler to open font browser. Lock icons positioned in card. |
| `FontPairCard.module.css` | Specimen typography styles. Card layout. |

### Font Browser — `FontBrowser.tsx` + `FontBrowserGrid.tsx`

**Current (verified):** `FontBrowser.tsx` and `FontBrowserGrid.tsx` exist in `TypographyTab/`. Current grid shows "Aa Bb Cc" style single-font previews.

**New behaviour:**
- Font browser opens as a **slide-in panel from the right** (`transform: translateX(100%)` → `translateX(0)`, 200ms ease-out). Overlay the full Detail Mode panel. Dismiss with ESC or close button.
- Each card in the grid shows: **a heading phrase in heading font (~24px) + one sentence of body copy in body font (~14px)**. The pairing context is immediately readable.
- Category filter chips above the grid (editorial, humanist, geometric, expressive, technical) — chip style using `--radius-full`, `--color-interactive` active, `--color-border-strong` inactive (same as harmony chips)
- Grid: 3 columns desktop, 2 tablet, 1 mobile
- Hovering a card: "Use this pair" button overlaid on the card
- Dismiss: ESC key + close button — `FontBrowser` already has this mechanism, verify and keep

**File changes:**
| File | Change |
|---|---|
| `FontBrowser.tsx` | Add slide-in panel wrapper (translate animation). Add category filter chips above `FontBrowserGrid`. Close on ESC (check if already implemented). |
| `FontBrowserGrid.tsx` | Change card rendering from single-font "Aa Bb Cc" to paired heading + body specimen. Add "Use this pair" hover overlay button. |
| `FontBrowser.module.css` | Slide-in panel styles: full-width overlay, `z-index: var(--z-50)`, transform transition. |
| `FontBrowserGrid.module.css` | Card redesign: paired specimen layout, hover overlay button. |

### Type Scale — `ScaleEditor.tsx`

**Current:** Scale rows showing levels with their sizes. Some editing capability for the ratio.

**New behaviour — expandable rows:**
- Default state: each level (Display, H1, H2, H3, H4, Body, Small, XS, Label) shown at its **actual rendered size** in the active heading/body font
- Expanded state (click any row): reveals an **inline text editor** — `contentEditable` or `<input>` — so user can type their own sample text and see it at that size. Also shows size/weight/line-height token values for that step. Lock icon per step.
- Scale ratio selector: displayed as a **visual comparison tool**. Selecting a ratio (1.125, 1.250, 1.333, 1.414, 1.500, custom) shows all 9 type levels reflow in real time. A small comparison indicator shows how much larger Display becomes relative to Body as the ratio changes.
- The ratio selector is already in `ScaleEditor.tsx` — this is a visual upgrade of the existing control, not new functionality.

**File changes:**
| File | Change |
|---|---|
| `ScaleEditor.tsx` | Add expandable row state (`expandedKey`). Expanded row: show inline text editor + token values. Ratio selector: upgrade to visual comparison layout (show before/after scale at a glance). |
| `ScaleEditor.module.css` | Row expansion animation. Ratio comparison display styles. |

## Components Tab — `ComponentsTab/` (Phase 2)

### Component Preview — `ComponentPreview.tsx`

**Current:** Small strip of components (Button, Input, Card, Badge, Tag, Tooltip, Alert).

**New behaviour:**
- Each component gets its own **named section** with a visual preview at ~1.5× current size
- State selector per component: Default → Hover → Disabled → Active → Focus (local `useState`, no store change)
- Preview background toggle: `var(--color-surface)` (light) ↔ dark surface — proves components work on both backgrounds
- This is a visual layout expansion of what already exists — the component rendering logic stays the same

**File changes:**
| File | Change |
|---|---|
| `ComponentPreview.tsx` | Expand to named sections per component. Add state selector. Add background toggle. |
| `ComponentPreview.module.css` | Section layout. State selector styles (segmented control pattern). Background toggle. |

### Component Token Overrides — `ComponentTokenSection.tsx`

**Current:** Token tables with "auto" badges showing each token's derived value. Read-only.

**New behaviour — interactive overrides:**
- `auto` badge is now a **clickable button**
- Clicking `auto` enters override mode: badge becomes a small `<input>` pre-filled with the current token value. User can type a custom hex or token reference.
- Badge changes to `custom` (amber color) when overridden
- `Reset to auto` button appears next to any overridden value
- **Overrides persist across SPACE** — the system regenerates but the overridden component token stays until manually reset
- Overrides stored in the existing `componentOverrides` mechanism in the store (verify: `store/color.ts` or `store/index.ts` passes `componentOverrides` to `buildTokenMap` — confirmed in `derived.ts` signature)

**Store note:** `buildTokenMap` already accepts `opts.componentOverrides?: Partial<ComponentTokenMap>`. Verify that the store slice passes user overrides to `buildTokenMap`. If the store already supports this, this is a UI-only change. If not, a new `setComponentOverride(component, token, value)` action is needed.

**File changes:**
| File | Change |
|---|---|
| `ComponentTokenSection.tsx` | Make `auto` badges interactive: click → input mode. Add `custom` badge state. Add `Reset` button per overridden token. Store overrides in local state (or dispatch to store if store supports it). |
| `ComponentTokenSection.module.css` | `.autoBadge` interactive styles. `.customBadge` amber color. `.resetBtn` small inline button. |
