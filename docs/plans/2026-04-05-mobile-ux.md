# Mobile UI/UX Improvement Plan — TYPESET v3
**Date:** 2026-04-05
**Status:** Draft
**Author:** Architecture review — Claude

---

## Executive Summary

TYPESET v3 is a desktop-first SPA that already contains a skeleton of mobile awareness: one breakpoint (`768px`), a `mobileShowPreview` toggle in the UI store, a slide-out/slide-in SplitPane on mobile, and a few specific component overrides. However the execution is incomplete in critical ways. The app is usable on mobile in a basic sense but falls well short of an "ideal" experience.

The core problems are:

1. **The SplitPane mobile mode works but the mental model is unclear** — there is no persistent UI element that tells the user they can switch between panels, making the toggle easy to miss.
2. **Touch targets are dangerously small** across detail tabs, the sessions drawer action buttons, color slot cards, and the type scale editor — most are 24-28px, well below the 44px minimum.
3. **The Detail Mode tab bar has no mobile scroll affordance** — 7 tabs at 3-letter abbreviations in a 768px-wide scroll container with no visual cue that it scrolls.
4. **The ColorPickerPopover positions itself relative to a viewport anchor** but does not account for virtual keyboard, resulting in it being hidden behind the keyboard on mobile.
5. **Zero responsive work exists** in 40+ detail-tab CSS module files — all grids, scale rows, and spacing rulers are desktop-only layouts.
6. **The OnboardingOverlay instructs users to press `Space`** — irrelevant and confusing on touchscreens.
7. **No PWA manifest, no `theme-color`, no service worker** — the app cannot be added to the home screen.
8. **No `prefers-reduced-motion` support** — the globally applied transition rule in `globals.css` runs on all devices including low-power ones.

This plan delivers a full mobile experience in three phases: critical fixes (Phase 1, ~4 days), enhanced touch experience (Phase 2, ~5 days), and polish plus PWA (Phase 3, ~3 days).

## Current State Audit

### What Works on Mobile Now

**Confirmed from code inspection:**

- `SplitPane.module.css` (line 69–98): At `≤768px`, both panels become `position: absolute; width: 100%`, and `mobileShowPreview` in the UI store drives `slideOut`/`slideIn` CSS transforms. The transition uses `--ui-duration-5` (0.30s ease). This is architecturally correct.

- `AppHeader.module.css` (line 217–234): At `≤768px`, the 3-way theme segment control is hidden and replaced with a single cycling button (`themeCycleBtn`). Icon buttons are enlarged to `40×40px`. Export button drops its text label. This is a good mobile override.

- `GeneratorFooter.module.css` (line 45–86): At `≤768px`, a prominent "Generate" button (`--ui-size-btn-xl` = 40px) and a "Preview" button appear; the desktop-only "Detail Mode" button is hidden. This is the right pattern.

- `ColorSlotCard.module.css` (line 178–191): At `≤768px`, cursor changes to `default`, the remove button is always visible (no hover required), and the lock button grows to `32×32px`.

- `RecipePillRow.module.css` (line 12–19): At `≤768px`, a right-edge mask gradient signals horizontal scroll. The pill row itself already uses `overflow-x: auto; scrollbar-width: none`.

- `SpaceHintBar.module.css` (line 28–30): Hidden on mobile — correct, the keyboard shortcut hint is irrelevant.

- `DetailMode.module.css` (line 96–125): Short labels switch at `≤900px`; the Preview button appears at `≤768px`.

- `ExportPanel.module.css` (line 246–266): Bottom-sheet pattern (`border-radius: 16px 16px 0 0; max-height: 85vh`), scrollable format tabs, full-width Copy button. Well executed.

- `ColorsTab.module.css` (line 60–62): Hides the `<kbd>` hint on mobile.

- `SignInPrompt.module.css` (line 19): Uses `min(420px, calc(100vw - 32px))` — safely clamped.

- `UpgradeModal.module.css` (line 19–23): Uses `min(480px, calc(100vw - 32px))` with `max-height: calc(100vh - 48px)`.

- `SessionsDrawer.module.css` (line 17): Uses `max-width: 90vw` on the drawer — safe on narrow screens.

- `ColorPickerPopover.tsx` (line 41–55): Listens to `touchstart` in addition to `mousedown` for outside-click dismissal.

- `ColorSwatches.tsx` (line 26–87): Full long-press touch drag implemented with haptic feedback (`navigator.vibrate(30)`), a 400ms long-press threshold, and a `data-slot-id` hit-testing approach via `document.elementFromPoint`.

- `index.html` (line 4): `<meta name="viewport" content="width=device-width, initial-scale=1.0">` — correct.

### What Is Broken or Missing

**Layout-level breakages:**

- **No `mobileTab` UI affordance.** The only way to get back to the generator from the preview is the "Back to generator" button in `LivePreview.tsx`, which renders as `display: none` and is only shown at `≤768px`. There is no persistent tab bar, bottom nav, or FAB that makes this discoverable. Users who tap "Preview" in the GeneratorFooter will not know how to return unless they find the back button at the very top of the scrolled preview.

- **`App.module.css` has no responsive rules.** The root `.app` container uses `height: 100vh; overflow: hidden`. On iOS Safari, `100vh` does not account for the dynamic browser toolbar (it uses the maximum viewport height). The correct fix is `height: 100dvh` (dynamic viewport height) or the `@supports` fallback pattern.

- **`GeneratorPanel.module.css` has zero responsive work.** The `.section { padding: var(--ui-space-8) }` — 16px — is fine, but the `.sectionResult` heading is `22px` which may be too large on very narrow screens. More critically, the lock button at `24×24px` does not meet 44px touch target minimums.

**Detail Mode breakages (every tab):**

- `ColorsTab`: `ContrastGrid.module.css` — the `.cell` rows use `display: flex; justify-content: space-between` with mono badges. On 375px screens these badges overlap the color labels.

- `ColorsTab`: `ShadeScaleSection.module.css`, `NeutralScaleSection.module.css`, `GreyscaleSection.module.css` — all use horizontal shade strip layouts with no wrapping.

- `TypographyTab`: `ScaleEditor.module.css` — the `.scaleRow` uses a flex layout with `stepLabel (48px)`, specimen text, and a `.meta` group containing multiple `.metaItem` columns. On 375px this will overflow or be illegible.

- `TypographyTab`: `FontBrowserGrid.module.css`, `FontPairCard.module.css` — virtually certain to overflow on 375px given they show paired specimen text.

- `SpacingTab`: `SpacingScaleSection.module.css` — the `.rulerRow` contains `.stepLabel (28px)`, `.tokenName (130px)`, `.bar (variable width)`, `.valueInput (52px)`, `.resetBtn`, and `.pxLabel`. Total minimum ~250px before bar width; on 375px with 32px padding this is impossible.

- `EffectsTab`: `ShadowBuilder.module.css` — shadow builders with multiple inputs will not reflow.

- `ComponentsTab`: No responsive work.

**ColorPickerPopover on mobile:**

The popover positions itself with `position: fixed` computed from `anchorRef.getBoundingClientRect()`. On iOS, when the virtual keyboard opens after tapping the hex input, the viewport shifts and the popover may be clipped behind the keyboard. No `visualViewport` resize handling exists. Additionally the hex text input needs a minimum 44px touch target.

**OnboardingOverlay on mobile:**

`OnboardingOverlay.tsx` tells users `Hit [space] to generate`. This instruction is actively misleading on touchscreens. The overlay should detect whether the primary input is touch and display "Tap Generate to start" instead.

**LandingTemplate (live preview) on mobile:**

`LandingTemplate.module.css` is entirely desktop-designed. The `.heroHeadline` is `var(--font-size-display, 62px)` — on 375px this will be huge and likely cause overflow. The `.featureGrid` is `repeat(3, 1fr)` — will overflow. None of this has `@media` rules.

**No PWA support:**

No `manifest.json`, no `theme-color` meta tag, no service worker, no `apple-touch-icon`, no `apple-mobile-web-app-capable`. The app cannot be added to the home screen on iOS or Android.

**No `prefers-reduced-motion`:**

`globals.css` applies `transition: background-color, border-color, color` on every element globally. No `@media (prefers-reduced-motion: reduce)` override exists anywhere in the codebase.

## Layout Strategy

### SplitPane on Mobile: Stacked Full-Screen with Persistent Tab Bar

The current slide-out/slide-in approach in `SplitPane.module.css` is the right mechanism. The missing piece is a **persistent bottom tab bar** that shows the user which panel they are on and provides a single tap to switch.

**Chosen approach: Persistent floating pill switcher at bottom of screen.**

- Add a `MobilePanelSwitcher` component rendered inside `App.tsx` below `<SplitPane>`, visible only at `≤768px`
- Two pill buttons: "Design" and "Preview", styled like the existing recipe pills
- Drives `showMobilePreview` / `hideMobilePreview` from the UI store
- Positioned `position: fixed; bottom: env(safe-area-inset-bottom, 16px) + 16px; left: 50%; transform: translateX(-50%)`
- In Detail Mode, the same switcher appears with "Detail" and "Preview" labels

**No swipe gesture on the SplitPane panels.** The panels contain horizontal-scrolling content (RecipePillRow, tab bar), so adding a global horizontal swipe listener would cause conflicts. The pill switcher is cleaner and more predictable.

### Navigation Patterns

- **AppHeader**: Stays as-is at mobile breakpoint — the existing 40px icon buttons are good
- **DetailMode tab bar**: Already horizontally scrollable. Add a right-fade mask so users know it scrolls
- **Sessions Drawer**: Remains a right-side slide-in. Needs touch target fixes and the action button group needs a redesign for narrow screens

### `100dvh` Fix

Replace `height: 100vh` in `App.module.css` with:
```css
height: 100vh;
height: 100dvh; /* dynamic viewport height — iOS Safari toolbar aware */
```

## Accessibility on Mobile

### Focus Management

Create `v3/src/hooks/useFocusTrap.ts` hook. Apply to: `SessionsDrawer`, `ExportPanel`, `SignInPrompt`, `UpgradeModal`.

Requirements:
1. On open: move focus to first interactive element
2. Trap Tab/Shift+Tab within the overlay
3. On close: return focus to trigger element

### Missing ARIA

- `ColorSlotCard`: No `role`, `aria-label`, or `aria-grabbed` on draggable cards
- `RecipePillRow` pills: No `aria-selected` or `role="option"`
- `DetailMode` tabs: Missing `role="tablist"` / `role="tab"` / `role="tabpanel"`
- `MobilePanelSwitcher` (new): Must use `role="tablist"` with `aria-selected`

### Reduced Motion

Covered above in `globals.css` changes.
